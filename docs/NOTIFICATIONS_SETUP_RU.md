# Настройка уведомлений об авариях (Telegram + MAX + SMS)

При возникновении аварийной ситуации на устройстве WatersysPro backend отправляет
оповещение пользователю. Каналы доставки:

- **Telegram (основной)** — сообщение боту в Telegram с описанием аварии.
- **MAX (мессенджер)** — сообщение в мессенджер MAX через VK WorkSpace Bot API.
- **SMS (резервный)** — SMS на телефон через SMS-шлюз (SMS Aero или Twilio).

Оповещения формируются на основе MQTT-данных, которые устройство уже публикует
(поле `emergency` в телеметрии и топик `alert`). **Доработка прошивки ESP32 не требуется.**

---

## 1. Как это работает

```text
ESP32 ──MQTT──▶ Mosquitto ──▶ Backend (server.js)
                                  │
                                  │ при переходе emergency.active false → true
                                  ▼
                          notificationService.js
                           ├── Telegram Bot API  (основной канал)
                           ├── MAX (VK Bot API)  (доп. канал)
                           └── SMS-шлюз          (резервный канал)
```

- Backend отслеживает **момент срабатывания** аварии (переход из неактивного в активное
  состояние) и отправляет уведомление сразу.
- **Эскалация**: если авария не сброшена, уведомление повторяется через
  `NOTIFY_REPEAT_MIN` минут, максимум `NOTIFY_REPEAT_MAX` раз (защита от спама).
- Дедупликация предотвращает повторную отправку при каждом пакете телеметрии.

## 2. Настройка Telegram

### 2.1. Создание бота

1. Откройте Telegram и найдите **@BotFather**.
2. Отправьте команду `/newbot`.
3. Укажите имя бота (например, `WatersysPro Alerts`) и username (должен
   оканчиваться на `bot`, например `watersyspro_alerts_bot`).
4. BotFather выдаст **токен** вида `123456789:AAH...xyz`. Сохраните его.

### 2.2. Определение chatId

Есть два способа:

**Способ A — указать вручную (рекомендуется):**

1. Откройте диалог со своим ботом и отправьте ему любое сообщение (например, `/start`).
2. Получите свой числовой ID. Это можно сделать через Telegram, написав боту
   [@userinfobot](https://t.me/userinfobot) — он вернёт ваш `id`.
3. Впишите полученный ID в переменную `TG_CHAT_ID`.

**Способ B — автоматическое определение:**

Оставьте `TG_CHAT_ID` пустым. При старте backend попросит написать боту любое
сообщение (после настройки токена), после чего chatId будет определён автоматически
через `getUpdates`.

### 2.3. Переменные окружения

```dotenv
TG_BOT_TOKEN=123456789:AAH...xyz
TG_CHAT_ID=123456789          # или оставить пустым для автопределения
```

## 3. Настройка MAX (мессенджер)

MAX — российский мессенджер. Оповещение в MAX здесь работает через **WQTT
MQTT-мост**: backend публикует сообщение в MQTT-топик моста, а мост доставляет
его в ваш чат MAX. Публикация выполняется через REST API платформы WQTT
(`POST https://dash.wqtt.ru/api/broker/messages/pub`) — исходящий HTTPS-запрос,
без публичного вебхука.

### 3.1. Требования

- **Токен WQTT** — выдан при регистрации в [dash.wqtt.ru](https://dash.wqtt.ru)
  (заголовок авторизации `Authorization: Token <token>`).
- **Топик моста** — MQTT-топик, в который публиковать сообщение, чтобы оно
  пришло в ваш чат MAX (например, `maxmsg`). Получить его можно у бота моста
  командой `инфо`/`/topics` (в ответе было: «подключен к id:... топики maxmsg»).

### 3.2. Проверка токена и подключение бота

1. Зарегистрируйтесь в dash.wqtt.ru и получите токен WQTT.
2. Подключите бота моста в MAX (бот выдал вам одноразовый ключ — отправьте его
   боту, получите подтверждение «доставка сообщений включена»).
3. Уточните у бота топик доставки (команда `инфо` → топики, например `maxmsg`).

### 3.3. Переменные окружения

```dotenv
WQTT_TOKEN=ваш_токен_wqtt
WQTT_TOPIC=maxmsg            # топик моста для доставки в чат MAX
WQTT_HOST=dash.wqtt.ru       # хост REST API WQTT
```

> Поле `message` в MAX не поддерживает HTML-разметку Telegram, поэтому backend
> отправляет текст с удалёнными HTML-тегами.

## 4. Настройка SMS (резервный канал)

Выберите одного провайдера: **SMS Aero** (для РФ) или **Twilio** (международный).

### 3.1. SMS Aero

1. Зарегистрируйтесь на [smsaero.ru](https://smsaero.ru).
2. В личном кабинете получите **email** (логин) и **API-ключ**.
3. Укажите подпись (sign) — согласованное имя отправителя.

```dotenv
SMS_PROVIDER=smsaero
SMS_PHONE=79001234567
SMS_FROM=WATERSYS
SMSAERO_EMAIL=you@example.com
SMSAERO_API_KEY=your_api_key
```

### 3.2. Twilio

1. Зарегистрируйтесь на [twilio.com](https://www.twilio.com).
2. Получите `ACCOUNT SID` и `AUTH TOKEN`.
3. Приобретите номер (номер отправителя `TWILIO_FROM`).

```dotenv
SMS_PROVIDER=twilio
SMS_PHONE=+79001234567
TWILIO_ACCOUNT_SID=ACxxxxxxxx
TWILIO_AUTH_TOKEN=xxxxxxxx
TWILIO_FROM=+15551234567
```

> Если SMS не нужен, оставьте `SMS_PROVIDER=none`. Telegram продолжит работать.

## 5. Параметры эскалации

| Переменная        | Описание                                | По умолчанию |
|-------------------|-----------------------------------------|--------------|
| `NOTIFY_REPEAT_MIN` | Интервал повторного уведомления (мин) | `10`         |
| `NOTIFY_REPEAT_MAX` | Максимум повторных уведомлений        | `5`          |

## 6. Проверка работоспособности

После настройки и запуска backend'а проверьте статус и отправьте тестовое сообщение:

```bash
# Статус каналов
curl http://localhost:3000/api/notify/status

# Тестовая отправка (Telegram + MAX + SMS)
curl -X POST http://localhost:3000/api/notify/test
```

Ожидаемый результат `GET /api/notify/status`:

```json
{
  "ok": true,
  "telegram": { "configured": true, "tokenOk": true, "username": "watersyspro_alerts_bot", "chatId": "123456789" },
  "max": { "configured": true, "tokenOk": true, "peerId": "123456789" },
  "sms": { "provider": "smsaero", "configured": true, "phone": "790****67" },
  "escalation": { "repeatMin": 10, "repeatMax": 5 }
}
```

## 7. Развёртывание

### Локально (без Docker)

```bash
cd backend
cp .env.example .env
# заполните TG_BOT_TOKEN, TG_CHAT_ID и SMS-параметры в .env
npm start
```

### Docker (local compose)

Добавьте переменные уведомлений в корневой `.env` (или `docker-compose.yml`
уже читает их с префиксом `TG_`, `SMS_` и т.д.). Затем пересоберите backend:

```bash
docker compose up -d --build backend
```

### Облако (Railway / docker-compose.cloud.yml)

Файл `.env.cloud` берётся через `env_file`. Заполните те же переменные в `.env.cloud`
(образец — `.env.cloud.example`).

## 10. Примечания

- **Telegram через long-polling** (не webhook) — backend сам инициирует запросы,
  поэтому работает и в облаке, и на локальной машине без публичного URL.
- **MAX через исходящий вызов VK API** — не требует публичного вебхука.
  Нужен `MAX_ACCESS_TOKEN` и peer id получателя (или его автоподхват).
- **SMS — платный сервис.** Настраивается как резервный канал; для экономии можно
  оставить только Telegram или MAX.
- Оповещение срабатывает при **переходе** устройства в аварийный режим. Если
  устройство уже было в аварии до запуска backend'а, первое уведомление придёт
  только при следующем сбросе/повторном срабатывании.
