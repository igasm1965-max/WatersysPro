# Руководство по диагностике и настройке Wi-Fi подключения

## Причины частых отключений

На основе анализа кода выявлены следующие потенциальные причины:

### 1. Проблемы с сигналом (наиболее вероятно)
- **Слабый RSSI**: Уровень сигнала ниже -75 dBm приводит к нестабильности
- **Интерференция**: Другие устройства Wi-Fi, Bluetooth, микроволновки
- **Многолучевое затухание**: Отражения сигнала в металлическом корпусе

### 2. Конфигурационные проблемы
- **Режим AP+STA**: Одновременная работа двух интерфейсов создает нагрузку
- **Конфликт каналов**: AP и STA работают на разных каналах
- **Настройки роутера**: WPA3, скрытый SSID, фильтрация MAC

### 3. Программные проблемы
- **Блокирующие операции**: TLS handshake MQTT занимает до 15 секунд
- **Watchdog конфликты**: Отключение WDT во время TLS handshake
- **Конкуренция ресурсов**: SD карта и Wi-Fi используют один SPI

### 4. Аппаратные проблемы
- **Нестабильное питание**: Просадки напряжения при работе насосов
- **Перегрев ESP32**: Высокая температура влияет на стабильность радио
- **Антенна**: Плохой контакт или повреждение антенны

## Диагностический чеклист

### Шаг 1: Сбор информации
1. **Проверьте логи Wi-Fi**:
   ```
   [WiFi] STA disconnected (reason X=REASON_NAME)
   [WiFi] RSSI before disconnect: -XX dBm
   ```

2. **Определите частоту отключений**:
   - Запишите время между отключениями
   - Отметьте, совпадают ли отключения с работой насосов

3. **Проверьте настройки роутера**:
   - Канал Wi-Fi (рекомендуется 1, 6 или 11 для 2.4GHz)
   - Ширина канала (20MHz стабильнее, чем 40MHz)
   - Режим безопасности (WPA2-Personal наиболее совместим)

### Шаг 2: Анализ сигнала
1. **Измерьте RSSI**:
   - Норма: -30 до -60 dBm (отлично)
   - Приемлемо: -61 до -75 dBm (удовлетворительно)
   - Проблемы: ниже -75 dBm (нестабильно)

2. **Проверьте стабильность сигнала**:
   - Мониторьте RSSI в течение 5 минут
   - Ищите резкие падения (более 10 dBm)

3. **Проанализируйте окружение**:
   - Другие сети Wi-Fi на том же канале
   - Металлические препятствия между устройством и роутером
   - Расстояние до роутера (рекомендуется < 10м)

### Шаг 3: Тестирование подключения
1. **Временное отключение AP**:
   - Временно отключите точку доступа устройства
   - Проверьте стабильность STA подключения

2. **Тест без MQTT**:
   - Отключите MQTT в настройках
   - Проверьте, уменьшилась ли частота отключений

3. **Тест с другим роутером**:
   - Подключитесь к мобильной точке доступа
   - Проверьте стабильность соединения

## Рекомендации по настройке

### Оптимальные настройки роутера
1. **Канал**: Фиксированный канал (1, 6 или 11), а не Auto
2. **Ширина канала**: 20 MHz для большей стабильности
3. **Режим безопасности**: WPA2-Personal (AES)
4. **DTIM interval**: 3 (по умолчанию, не менять)
5. **Beacon interval**: 100 ms (по умолчанию)

### Настройки устройства
1. **Режим Wi-Fi**: STA только при постоянном подключении
2. **Мощность передачи**: Максимальная (если поддерживается)
3. **Sleep mode**: Отключен для стабильности

### Конфигурация кода (требует перепрошивки)

#### 1. Увеличение таймаутов (в `config.h`):
```cpp
#define WIFI_ATTEMPT_TIMEOUT_MS 15000  // было 10000
#define MAX_WIFI_BACKOFF_MS 120000     // было 60000
#define WIFI_MAX_ATTEMPTS 10           // было 5
```

#### 2. Оптимизация режима (в `wifi_manager.cpp`):
```cpp
// После успешного подключения
if (WiFi.status() == WL_CONNECTED && WiFi.softAPgetStationNum() == 0) {
    WiFi.mode(WIFI_STA);
    Serial.println("[WiFi] AP disabled for better stability");
}
```

#### 3. Мониторинг сигнала (добавить в `loopWifiManager`):
```cpp
static unsigned long lastRSSICheck = 0;
if (millis() - lastRSSICheck > 30000) { // Каждые 30 секунд
    lastRSSICheck = millis();
    if (WiFi.status() == WL_CONNECTED) {
        int rssi = WiFi.RSSI();
        if (rssi < -75) {
            Serial.printf("[WiFi] Warning: Weak signal (%d dBm)\n", rssi);
        }
    }
}
```

## Экстренные меры при частых отключениях

### 1. Немедленные действия:
1. **Перезагрузите устройство** и роутер
2. **Измените канал Wi-Fi** на роутере
3. **Уменьшите расстояние** между устройством и роутером
4. **Уберите металлические препятствия**

### 2. Временные решения:
1. **Отключите MQTT** через веб-интерфейс
2. **Используйте кабель Ethernet** с адаптером ESP32-Ethernet
3. **Настройте репитер Wi-Fi** между устройством и роутером

### 3. Долгосрочные решения:
1. **Установите внешнюю антенну** для ESP32
2. **Используйте mesh сеть** для лучшего покрытия
3. **Рассмотрите переход на LoRa** для критичных данных

## Диагностические команды через Serial

### Получение статуса Wi-Fi:
```
[WiFi] State: CONNECTED, Attempts: 0, AP restarts: 1, RSSI: -53, Clients: 0
```

### Детальная информация:
```
Mode: AP STA 
STA IP: 192.168.3.13
Gateway: 192.168.3.1
SSID: Keenetic-NCC
BSSID: AA:BB:CC:DD:EE:FF
Channel: 6
AP IP: 192.168.4.1
AP Clients: 0
AP SSID: WSystem-F4E9
```

### Проверка стабильности соединения:
1. **Пинг шлюза**: `ping 192.168.3.1`
2. **Пинг устройства**: `ping 192.168.3.13`
3. **Проверка потерь**: Мониторинг в течение 5 минут

## Интерпретация кодов отключения (reason codes)

| Код | Значение | Рекомендации |
|-----|----------|--------------|
| 2 | AUTH_EXPIRE | Проблемы с аутентификацией, проверьте пароль |
| 4 | ASSOC_EXPIRE | Таймаут ассоциации, увеличьте таймауты на роутере |
| 15 | 4WAY_HANDSHAKE_TIMEOUT | Проблемы с рукопожатием WPA2, используйте WPA2-Personal (AES) |
| 200 | BEACON_TIMEOUT | Потеря сигнала, проверьте RSSI и расстояние |
| 201 | AUTH_REJECT | Неверный пароль или несовместимый режим безопасности |
| 202 | ASSOC_FAIL | Проблемы с ассоциацией, попробуйте другой канал |

## Профилактические меры

### Еженедельная проверка:
1. **Очистка логов** для предотвращения переполнения
2. **Проверка свободного места** на SD карте

3. **Резервное копирование** настроек

2. **Обновление роутера** до последней прошивки
3. **Ревизия сетевой инфраструктуры**

## Заключение

Частые отключения Wi-Fi обычно вызваны комбинацией факторов. Систематический подход к диагностике и настройке позволяет значительно улучшить стабильность соединения. Начните с простых шагов (проверка сигнала, настройка роутера) и постепенно переходите к более сложным решениям (аппаратные модификации, оптимизация кода).

Помните: стабильное Wi-Fi соединение критически важно для удаленного мониторинга и управления системой водоочистки.
