## 🔴 Приоритет 1 — Функциональные «заглушки»

### 1.1. Связать переключатель «Автоматическая промывка» с реальным управлением
- **Проблема:** `autoFlush` в [`mobile/src/screens/SettingsScreen.tsx:158`](../mobile/src/screens/SettingsScreen.tsx:158) сохраняется только в `AsyncStorage` и никуда не передаётся.
- **Задача:** отправить значение в MQTT/backend при изменении ИЛИ убрать переключатель из UI как неработающий.
- **Реализация (вариант):**
  - [ ] Добавить MQTT-команду/топик для управления автопромывкой (например, publish в `watersystem/cmd`).
  - [ ] В ESP32 добавить обработку этой команды (включить/отключить `flags.filterCleaningNeeded` / расписание промывки).
  - [ ] В `SettingsScreen` отправлять команду через `MqttService` при переключении.
- **Критерий готовности:** переключение в приложении реально запускает/останавливает промывку на контроллере.

### 1.2. Решить судьбу LoginScreen / JWT-авторизации
- **Проблема:** `LoginScreen` помечен deprecated и не подключён в [`mobile/App.tsx`](../mobile/App.tsx). Backend имеет `/api/auth/*`, но приложение работает только через PIN.
- **Задача (выбрать один путь):**
  - [ ] Вариант A: внедрить `LoginScreen` в поток приложения (регистрация/вход, JWT, привязка устройства).
  - [ ] Вариант B: явно удалить `LoginScreen` и пометить auth-функции backend как неиспользуемые (снять из списка поддерживаемых функций).
- **Критерий готовности:** поведение приложения соответствует документации (либо есть полноценный вход по аккаунту, либо явно указано, что используется только PIN).

### 1.3. Описать путь получения учётной записи для потребителя
- **Проблема:** `ALLOW_REGISTRATION=false` по умолчанию в [`backend/src/server.js:56`](../backend/src/server.js:56) — самостоятельная регистрация выключена.
- **Задача:** определить и зафиксировать процесс создания учётной записи (администратором или временным включением регистрации) и отразить его в инструкции.
- **Критерий готовности:** раздел «где зарегистрироваться» в инструкции рабочий и реалистичный.

### 2.2. HTTPS/WSS для веб-интерфейса ESP32 ✅ (оценено)
- **Проблема:** admin-токен передаётся по HTTP ([`src/web_server.cpp`](../src/web_server.cpp:38), `ENABLE_WSS=false` в [`include/config.h`](../include/config.h:35)).
- [x] **Решение принято:** не включать HTTPS/WSS на ESP32 из-за дефицита Flash (~15% свободно) и RAM. Риск компенсирован короткоживущей settings-сессией (`X-Settings-Session`, TTL 30 мин) и привязкой к IP.
- [x] Документировано: ограничение доступа к Settings через сессию уже реализовано в [`web_server.cpp`](../src/web_server.cpp:112).
- **Критерий готовности:** достигнут — решение зафиксировано в этом плане.

### 2.3. Проверка отсутствия секретов перед релизом ✅
